# 0.7.3-alpha 名称与数据迁移

历史说明：0.7.4-alpha 已按用户要求移除本页所述兼容读取，但尚未进入 beta。未转换的数据仍应先使用 0.7.3-alpha。

此版本用于在进入 beta 前转换旧数据。开发侧仅进行了构建及非游戏检查，实际存档转换由用户执行；尚未制作 beta。

## 名称对应

| 项目 | 旧名称 | 新名称 |
| --- | --- | --- |
| 显示名称 | Sable Physical Contraptions | Create: Sable Contraptions |
| Mod ID | `sable_physical_contraptions` | `create_sable_contraptions` |
| JAR 前缀 | `sable-physical-contraptions` | `create-sable-contraptions` |
| 诊断命令 | `/spc`、`/spc_client_profile` | `/csc`、`/csc_client_profile` |

中文名为「机械动力：物理动态结构」。版本为 **0.7.3-alpha**，许可证保持 LGPL-3.0-or-later。

## 转换步骤

1. 游戏关闭后备份完整存档和配置。保留旧版本 JAR 供备份存档回退使用。
2. 从实例 `mods` 移除旧版本，安装 `create-sable-contraptions-0.7.3-alpha.jar`。不要同时安装两个版本；客户端和服务端使用相同版本。
3. 进入存档，加载各维度中需要保留的旧物理机构，确认控制、子结构、碰撞、库存及流体正常。旧结构 UUID 保留，无须为了改名手动重新创建所有机构。
4. 检查玩家背包、箱子和其他储存位置中的旧矿车结构物品。逐一在合适的位置放置，确认恢复成功，再用原来的收起方式重新收起；需要继续运行的也可以保持已放置状态。不要只移动物品槽位或复制物品，这不会重写内部快照。
5. 正常保存、退出并重新进入，核对机构、物品数量、流体与配置。保留转换后的存档备份，再反馈是否可以制作 beta。

进入一次世界只会处理实际读取的数据；未加载的实体、其他未进入的维度、未打开的其他存档，以及尚未放置的矿车物品可能仍包含旧键。若不能确定全部转换完成，应继续保留此 alpha 及旧数据读取能力，不宜直接切换到删除兼容读取的版本。

## 自动迁移范围

- 读取旧动态结构标记、物理子结构归属、停转状态、矿车物品快照及碰撞钻头状态；正常后续序列化使用新键。迁移只处理本 Mod 的字段，不递归替换其他 Mod 或物品内的文本。
- 读取 Sable 子世界上的旧管理标签，并转换为新标签；保持关联 UUID。
- 在 Sable 解析旧加载票据类型前转换名称，并标记票据保存数据为需要保存。
- 新配置文件不存在时，复制同目录的旧 `sable_physical_contraptions-client.toml` / `-server.toml` 为对应 `create_sable_contraptions-*` 文件。覆盖范围包括实例 `config`、`defaultconfigs` 的服务端模板及当前存档 `serverconfig`。
- 已有的新配置优先；旧配置文件保留，不覆盖、不自动删除。若要调整设置，应编辑新名称配置或使用 Mods → Create: Sable Contraptions → 配置。

已迁移的存档不保证能由旧版本读取。需要降级时应恢复完整备份，不要直接用旧 JAR 打开转换后的存档。

## 后续安排（已更新）

用户随后决定在 0.7.4-alpha 提前移除旧名称读取与配置迁移代码，并继续进行 alpha 验收；beta 仍需另行明确决定。这里的“删掉旧数据”指停止保留旧格式兼容路径和不再写旧键，不会扫描删除用户存档、旧配置或备份。历史更新记录及必要的版权署名仍保留。

迁移检查覆盖字段优先级、重复迁移、负载引用保留、配置不覆盖及票据改名前后的调用顺序；实际 Minecraft 存档迁移仍需验证。
