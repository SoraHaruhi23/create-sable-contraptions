# Sable Physical Contraptions — Create 动态结构物理化实验版

Minecraft 1.21.1 / NeoForge 21.1.228+ / Java 21。
加载声明接受 Sable 2.0.3+、Create 6.0.10+，仍须满足上游各自的依赖约束；不保证任意未来版本兼容。
安装 `build/libs/sable-physical-contraptions-0.7.2-alpha.jar`，移除本 Mod 旧版，不要安装 sources 包。

## 0.7.2 装配源头破坏保护

- 本 Mod 的矿车结构及其稳定子结构上的钻头不再选择矿车装配站作为破坏目标；同时保护出发站和沿途/目的装配站，物品恢复的矿车也适用。
- 共用保护覆盖结构家族自身的物理体、受控结构的原生 controllerPos（轴承、滑轮、活塞等）及龙门结构当前支撑轴所在同向轴线。子结构继承父结构控制器保护。
- 原生目标选择、碰撞目标投递、保存目标恢复和最终破坏均检查保护；取消旧目标时清理破坏进度、等待重试和碰撞钻头标记，避免旧存档目标反复停转。
- 不修改碰撞形状或给予穿透能力；真实障碍仍按现有碰撞规则处理。普通火车、非本 Mod 动态结构与玩家手动破坏不进入此保护。
- 仅递增第三位为 0.7.2-alpha。未启动游戏，装配站场景仍待实机验证。

## 0.7.1 恢复保护、转弯扫掠与停转定位

- 嵌套矿车恢复使用家族事务：子结构加载、挂载或加入世界失败时，逆序清理已创建的物理体、票据与实体；全部成功后再清除恢复快照。根结构被拒绝加入也进入回滚。
- 矿车在工作部件运行前检查车身平移与转向的组合扫掠，检测旋转中途的角点；阻挡后回退位置/朝向并停止，后续重新检测。继续保留工作部件的停转处理。
- 工程师护目镜区分真实碰撞、区块未加载、检测预算不足、世界边界及结构数据不可用。看向受阻结构时，可用 Create 原生轮廓标记阻挡方块；Mods → 配置提供高亮开关。
- 常规新文本覆盖简体中文、繁体中文、英语、日语。关闭开发诊断不会关闭 HUD 原因记录。
- 按本次要求只递增第三位，保持 0.7 与 alpha。验证范围和进度兼容性说明见 [0.7.1 审查记录](REVIEW-0.7.1.md)。未启动游戏。

## 0.5.11 拆卸占位替换及放置初始化顺序

- 矿车、轴承等使用共享拆卸流程的结构允许清除可替换占位方块（包括铁轨），并使用 Create 的 noDropWhenContraptionReplaceBlocks 配置决定替换掉落。虚拟矿车锚点所在的装配站及活塞特殊槽不在普通清除列表中。
- 不再把全部非空气目标视为拆卸失败。仍检查重复目标、加载状态和世界边界；无法破坏的目标，以及原版不允许的无碰撞部件覆盖实心障碍情况，会保留物理结构及库存，而非丢弃被阻挡的结构方块。
- 物品物理快照从 onEntityCreated 推迟到服务端 EntityJoinLevelEvent 恢复，此时玩家选定的方向、挂载及最终坐标已经设置。首次 hold 前更新旋转和挂载高度，覆盖收起时保存的旧姿态。
- 首次定位后将上一帧姿态与当前姿态对齐并清零推导速度，避免客户端从分配时姿态插值到放置姿态、再据此把矿车拉离轨道。
- 保留客户端和服务端耗时诊断。现有计时未显示 1–2 秒瓶颈，不能据此宣称卡顿已解决；本版修复已定位的放置错位原因，未启动游戏。

## 0.5.10 装配站乘客兼容及客户端卡顿诊断

- 保留已确认有效的高度、自碰撞修复。实际反馈计时：服务端恢复 3.94 ms、NBT 加载约 0.16 ms，不能解释 1–2 秒卡顿；未将物品恢复改为异步或分帧。
- 修正装配站只检查第一个乘客的冲突：存在物理矿车结构时优先寻找该结构，避免玩家排在前面导致跳过拆卸；其他矿车保留原规则。
- 拆卸预检查记录空间占用、目标重叠、未加载等具体原因，仍不覆盖障碍方块。`/spc cart_status` 显示最近拆卸结果、当前轨道和装配站动作；尚未确认反馈结构属于哪种拒绝原因。
- 新增客户端 `/spc_client_profile start`（记录 60 秒）和 `/spc_client_profile show`（停止并显示）。请 start 后放置问题矿车，卡顿结束执行 show。记录客户端区块处理（包括普通区块）和物理化结构的 Create 虚拟初始化次数、累计及最长耗时。
- 客户端计时不覆盖网络传输、底层包解码、GPU 编译及全部渲染阶段；只保存计时，不读取库存内容。未启动游戏，尚未确认放置卡顿已解决。

## 0.5.9 矿车自碰撞修正与放置耗时诊断

- 保留 0.5.8 已确认有效的挂载高度修复。
- 原版四种铁轨没有实体碰撞形状，自定义几何扫掠不会因其外观高度阻挡；模组修改轨道形状的情况仍以实际诊断为准。
- 修正 Sable 实体碰撞路径未排除矿车自身物理结构的问题：仅承载矿车忽略所属主/子结构的实体碰撞；玩家、其他实体、其他物理结构以及世界障碍仍正常碰撞。尚未在反馈存档中确认低速是否完全消失。
- `/spc cart_status` 新增最近一次阻挡及其发生时间、速度控制倍率、巡航速度，以及此会话中该矿车的放置分阶段耗时。放置计时含结构恢复调用总耗时、物理分配、区块准备、方块创建、方块实体 NBT 加载和物理初始化；子结构各阶段累加。
- 计时不包含后续区块传输/客户端解码，不序列化或打印物品数据。放置后在目标矿车旁执行命令并保留完整输出，可区分同步 NBT 加载瓶颈与后续同步卡顿。
- 此版未将恢复改成分帧或异步，也不宣称解决大 NBT 放置卡顿；需要实际阶段耗时定位。未启动游戏。

## 0.5.8 矿车装配高度与大 NBT 放置开销

- 物理矿车结构的乘客挂载高度统一为 0.25 格，抵消平轨 Y 偏移 0.0625 与原版乘客偏移 0.1875；使结构底部回到原方块网格，避免顶部约 1 像素的多余碰撞。仅用于物理化 MountedContraption，普通矿车乘客、稳定子结构和火车不受此挂载修改影响。
- 客户端显示/实体同步、逻辑运动、Sable 目标及碰撞均读取同一挂载点；保留 0.5.7 的轨道中间坐标修复，不增加碰撞容差。
- 放置时借用只读物理快照，避免复制整棵含嵌套库存的 NBT；对交给方块实体加载的 NBT 和可变逻辑数据仍独立复制。子结构同样避免重复复制物理快照。
- 恢复阶段缓存同种方块状态解码，移除在已有方块更新及新区块初始同步之外的重复更新通知。库存数据不裁剪、不截断。
- 这是对已识别重复开销的优化，尚未在用户大 NBT 物品上测量 1–2 秒卡顿改善幅度；没有启动游戏。

## 0.5.7 矿车轨道中间坐标误碰撞修复

- 按要求撤回 0.5.5/0.5.6 的钻头最近表面和切削宽度改动，恢复 0.5.4 的目标中心朝向半球判断；下方两节仅记录历史，不代表当前规则。
- 原版轨道移动在调用 Entity.move 前暂时将矿车 Y 设为轨道格高度，结束后才恢复 getPos() 的轨道实际高度。碰撞检查过去在中间阶段同步乘客，导致普通方块也出现地面重叠；平轨上误差为 1/16 格。
- 轨道移动阶段改用 getPos() 投影后的起点及终点检查结构，检查结束恢复逻辑实体位置。不整体抬高物理结构、不忽略地面、不修改碰撞容差；非轨道移动继续使用原请求。
- 保留主结构/子结构扫掠、前方真实障碍、高速阻挡和最终位置复查。矿车转弯完整旋转扫掠仍未实现。
- 新增普通方块在平轨临时高度误碰地面、实际轨道高度通过、负坐标、反向、高速前墙、实际下落及调用顺序检查；未启动游戏。

## 0.5.6 钻头切削宽度限制

- 修正仅检查前方半空间仍会挖到前下方地面边缘的问题。最近表面还必须位于钻头轴线半径 0.5 格的切削范围内，边界相切不算切削。
- 水平钻头不会选择完全位于下一排的地面；上方和侧面相邻排同样受限。范围随钻头朝向旋转，向下钻头仍可挖下方，范围内的斜前方阻挡仍可挖掘。
- 继续共用目标发现、碰撞目标、进度及最终破坏过滤。不会通过取消物理碰撞来放行结构；若结构本身嵌入地面，仍可能停转。
- 新增贴地前进、相邻排、向下钻掘、斜前方及旋转范围的非游戏回归检查。未进入游戏验证截图中的实际布局。

## 0.5.5 钻头侧面目标修复

- 用目标实际碰撞形状的最近表面判断钻头朝向半球，替换方块中心判断。沿侧墙或地面滑行时，方块中心稍微位于前方不再足以触发挖掘；前方及斜前方表面仍可挖掘。
- 世界方块与其他物理结构均使用世界空间形状；复合形状按最近表面判断。原版目标发现、碰撞目标、持续挖掘和最终破坏共用此限制，旧的非法目标会取消。
- 保留真实侧面碰撞停转。本次修改针对侧面挖掘，不宣称已消除此前诊断中的深板岩碰撞或修复该矿车的全部起步问题。
- 保留 `/spc cart_status` 诊断。

## 0.5.4 无法起步问题诊断包

针对含保险箱、木桶、机械手和钻头的矿车可以装配但完全不能起步的反馈，增加只读诊断。尚未获得该结构的布局和运行状态，不能确认原因或宣称已经修复。

站在目标矿车旁执行 `/spc cart_status`，选择 16 格内最近的物理矿车。输出包括矿车实体编号、坐标、速度、几何停转与结构停转状态、最近扫掠的请求位移和结果、发生碰撞的部件局部坐标与障碍世界坐标、查询预算/未加载区块原因，以及请求停转的工作部件。若附近有多辆矿车，请核对输出坐标。

诊断读取已记录的检测结果，不重新触发钻掘、机械手、库存传输或运动。请提供完整输出，以判断是碰撞、工作行为、结构规模还是驱动状态。没有因这次反馈移除任何组件的支持，也没有更改碰撞或工作规则。

## 0.5.3 矿车碰撞与高速移动修复

- 主矿车结构及稳定子结构都参与整段平移扫掠，使用实际方块碰撞形状和当前朝向；此前只有子结构参与矿车的预检查。
- 在矿车实际 `move` 请求之前检查位移，而不是等乘客实体 tick 后再检查。轨道额外的位置修正会在矿车 tick 结束时复查；被拒绝的移动不提交给物理结构。保留碰撞停转、钻掘目标归属和障碍移开后的恢复。
- 装配站查询使用 Create 原有的矿车碰撞上下文，因此可以进入装配站；其他世界障碍仍参与扫掠，不全局取消装配站碰撞。
- 客户端 tick 将承载矿车的位置、上一帧位置和乘客位置对齐至 Sable 物理插值，修复上一版只平移矿车模型而没有同步客户端碰撞实体的问题。逻辑结构外包围盒同步至实际物理结构范围；外包围盒仍不是每个方块的碰撞形状。
- 新增高速穿过薄墙、反向、斜向、顶部间隙及移动入口、装配站上下文、客户端碰撞同步检查。本版修复针对实际平移请求，矿车转弯的完整旋转扫掠仍未实现。

## 0.5.2 矿车交互与生命周期修复

- 承载矿车被移除时，清理其逻辑实体及稳定子结构代理。无法正常拆卸的结构保留真实方块和库存，释放约束成为普通 Sable 物理结构，不强制覆盖世界方块；只移除合成的不可见矿车锚点。
- 物理步前检查仍引用已移除矿车的旧代理，避免它们因失去乘客 tick 而永久残留。无载具的矿车结构代理在 100 tick 初始化宽限后清理；不扫描删除任意无主物理结构。
- 物理步前重新对齐矿车乘客位置并提交结构姿态；矿车渲染使用所载结构的 Sable 插值位置，补偿矿车自身插值与轨道渲染偏移，不在渲染过程中移动游戏实体。
- 普通可乘坐矿车允许玩家与不可见结构代理共同乘坐，仍限制一个实际乘客，保留潜行及原有扳手/耦合交互。箱子和动力矿车不因此变为载人矿车。
- Sable 对矿车上结构（含稳定子结构）的敲击冲量传给承载矿车；沿用 Sable 的冷却、属性和力度计算，按结构总质量换算为矿车速度并沿轨道投影，耦合矿车共同受力。普通电梯、轴承和列车不走此分支。
- 扳手收纳继续保存快照并移除对应物理结构，与破坏矿车后保留真实方块的流程分开。

本版为 0.5 系列兼容修复，保留 alpha。

## 0.5.1 子结构、动画与快速对接修复

- 子结构锚点根据父结构当前变换和轴承连接点计算；父轴承更新后及物理步开始前统一提交整组子结构姿态，避免使用过期的乘客位置。
- 主轴承底座使用物理结构的插值角度，停止按未减速的客户端原转速外推；机械、风车与时钟轴承共用此原则。
- 便携式存储接口的移动端动画根据实际物理位置、朝向和固定接口同步的传输计时器伸缩，两种渲染后端继续使用原移动部件动画。
- 提前扫描距离保持不变，但只在接口附近快速制动；原连接流程确认停靠后速度为零，离站约 3 tick（0.15 秒）恢复原速。到连接位置前保留短距离低速接近，避免停在连接范围之外。
- 子结构碰撞参与主结构的运动检查；轴承按子结构保持稳定朝向的圆弧轨迹检查，直线机构按平移检查。检测普通世界和其他物理结构，阻挡主结构、解除后恢复，并沿用原停转提示。同一家族不互相阻挡。
- 矿车接入子结构平移预检与原矿车停转逻辑；轨道转弯时的朝向变化尚无完整旋转预测，仍需游戏验证。
- 子结构查询有 32768 个扫掠分段、每条轨迹 2048 段及比较次数预算，超出时保守停转。没有放开列车转换。

未启动游戏，实际轨迹、动画、多人同步及碰撞效果仍待验证。

## 0.5.0 矿车、稳定子结构与接口减速

- 物理父结构装配出的稳定子结构分别建立物理结构，沿用 Create 的稳定朝向与父子跟随。列车及其子结构不启用转换。

- 矿车扳手收纳保存实时方块、方块实体及稳定子结构快照；重新放置分配新的物理 UUID，保留原尺寸与收纳权限检查。

- 便携式存储接口提前扫描运动路径上的同类、反向、未受红石禁用且可连接接口，接近时减速，原传输流程完成后逐步加速。直线机构、轴承、矿车及其稳定子结构参与检测。
- 接口预扫描当前支持普通世界中的固定接口，最大前视约 4.5 格；不主动对接另一个移动 Sable 结构中的接口。实际传输仍由 Create 原逻辑执行。

## 0.4.0 新增直线机构与碰撞钻掘

- **普通绳索滑轮**：装配为 Sable 结构，沿用 Create 的绳长、方向、镜像滑轮、序列行程及放置模式；绳索固定端跟随真实插值姿态。

- 保留禁用状态、不可破坏方块及铁轨排除、自身结构保护；目标离开可达范围或钻头被移除时取消碰撞钻掘。其他工作部件仍保留各自原移动行为。
- 本版仅接入从普通世界装配的机构，尚不支持在另一物理结构内部启动活塞、滑轮或龙门机构。旧的未转换动态结构需拆卸并重新装配。

## 0.3.0 新增轴承

- **机械轴承（旋转轴承）**：沿用 Create 的转速、正反转、序列角度限制及旋转/放置/归位后放置模式。支持 X/Y/Z 三轴。
- **风车轴承**：沿用风帆数量要求、方向设置、发电转速和应力容量。运行中每 5 tick 重算真实风帆及覆面板材料计数，通过原更新入口刷新发电。
- **时钟轴承**：时针、分针各自建立一个 Sable 结构，保留 Create 的时间目标、指针顺序和 12/24 小时模式。拆卸前检查两根指针的归位目标及相互占位；这不是跨文件事务保证。
- 轴承共用真实库存、流体、红石、MovementBehaviour、运行中编辑和自挖保护。动态结构控制器按钮仍控制对应的工作部件过滤类别；过滤条件在装配前设置。

- 姿态从 Create 的旋转基向量生成，绕原锚点方块中心旋转；运行中质心变化不会改变固定点。客户端工作部件使用真实结构的插值角度。
- 拆卸位置、90 度取整和方块状态旋转使用 Create 的 StructureTransform；迁移当前方块实体数据、执行方块实体变换、旋转胶水边界，并将站立跟随实体映射到落位姿态。目标有世界方块时拒绝拆卸，不覆盖它们。
- 保存关联沿用 SPCSubLevel 和旧版物理用户数据键，增加旋转四元数。旧电梯缺少旋转字段时按单位旋转读取；不会自动转换旧的非物理轴承实体。

## 实现和保存

`ElevatorBridge` 负责 Sable 迁移、UUID、局部坐标和胶水；`ElevatorPhysics` 用约束及物理步姿态校正跟随 Create 的目标位置。
电梯与普通滑轮使用竖直目标，活塞和龙门滑块使用轴向目标，轴承使用绕方块中心的旋转目标；均由 Create 控制，并非自由动力学平台。Sable 负责真实区块、同步、玩家碰撞和保存。
平台使用持久加载票据且禁止自动分裂，直到拆卸。Create 代理的静态网格和重复碰撞被隐藏。

`ElevatorActors` 维护移动行为及真实方块的对应；`PhysicalStorage` 将原移动行为接到实际方块能力。
物品聚合要求无方向的 `IItemHandlerModifiable`，流体要求无方向的 `IFluidHandler`。
仅提供其他或有方向能力的第三方库存仍可按其原方式使用，但不保证进入移动行为的公共库存。

`ElevatorEditing` / `LevelPlotMixin` 实时更新方块清单，加载后及拆卸前扫描区块核对。
拆卸使用实际方块及当前方块实体数据，要求目标格为空；活塞头/杆落在原缸体内时按 Create 规则收回，不替换缸体。物理结构缺失时不会从旧逻辑快照生成第二份结构。
行为 stopMoving 的数据会回写。玩家破坏工作部件前也尝试归还行为持有的工具，再执行正常掉落。

## 当前边界

用户已确认 0.1.3 控制器修复，并反馈 0.2.0 上行乘坐抖动、接触信号异常、钻头误挖自身。0.2.1 针对这三项修改了代码：目标位置延迟到物理阶段应用、恢复真实触点 tick、按 Sable UUID 排除自身破坏目标。修复效果尚待游戏验证。
放行装配不代表所有第三方组件、座位、嵌套运动结构、多方块机器和移动交互已完整兼容。
0.3.0 的三类轴承、旋转乘坐、自动门、钻头工作与掉落收集、多人一致性及保存重载均需要后续实机验证。

- 碰撞钻掘针对钻头自身的扫掠体积；不将整台机器的所有阻挡方块作为钻头目标。高速旋转和双方同时运动的跨结构钻掘仍需实机验证。
- 爆炸、命令或第三方直接移除工作部件时，尚不能保证回收行为临时持有的物品。
- Sable 与 Create 跨文件保存/批量迁移不是崩溃原子事务，异常回调和进程崩溃下不能保证绝无损失。
- 其他结构的碰撞采用当前姿态，没有完整求解双方同时高速移动/旋转。抖动、穿透和大型平台性能未验证。
- 大规模平台持续加载和定期扫描的性能未验证；未执行列车运行回归。

后续游戏验证可覆盖三轴机械轴承、风车发电与改向、时钟双指针及模式切换、不同角度拆卸、工作部件与控制器、旋转中保存重载。电梯后续验证包括：停靠开门与出发关门；向下钻掘、物品进入平台箱子并恢复行驶；运行中增删组件；编辑库存后保存重载及拆卸；多人同时选层。
